I want you to add a new **Landing Page Generator** module to my existing Electron desktop project.

The current project already uses:

- Electron
- JavaScript
- HTML
- CSS
- Photoshop automation / JSX integration

Do not rebuild the entire application. Add this as a new module/page while preserving all existing working modules.

The purpose of this feature is to reduce manual work when creating ecommerce landing pages from screenshots.

# MAIN GOAL

The user should be able to upload:

1. An optional **Single** image for the top of the landing page
2. One or multiple landing-page screenshots

The system should then reconstruct those screenshots into a **structured, editable Photoshop PSD**, not simply paste the screenshots as flat images.

The goal is:

Screenshot(s) → editable PSD structure

The final PSD should require only minor manual correction.

# CORE LANDING PAGE RULES

## Canvas width

The final landing page PSD must always be:

1000 px wide

## Canvas height

Height is dynamic / content-driven.

Do not force any fixed height.

The PSD can be very long as long as the entire landing page content is included.

## No artificial whitespace

There must be no automatically added white gaps between landing-page sections.

Do not add:

- unnecessary padding
- blank separators
- fixed empty areas between LP screenshots
- artificial white borders

The only intentional reserved area is the optional Single section at the top.

# SINGLE IMAGE RULE

Landing pages often have a separate ecommerce "Single" image at the top.

Typical original Single source size:

600 × 600 px

When placed inside the generated landing page PSD, the Single section must occupy:

1000 × 1000 px

The Single should be placed at the very top of the landing page.

If the user uploads a Single image:

- place it in the top 1000 × 1000 section
- scale it proportionally to fill the intended Single section
- do not distort the image

If the user does NOT upload a Single:

- still allow generation
- leave a clearly defined 1000 × 1000 editable/reserved space at the top
- the designer can manually add the Single later

The LP body starts immediately after this 1000 px-high section.

# LANDING PAGE SCREENSHOT INPUT

The user may upload:

- one long screenshot

OR

- multiple screenshots / split parts

Multiple screenshot upload is required.

Support:

- drag and drop
- multi-file selection

The order in which the user uploads or arranges the screenshots must be the exact order used in the final PSD.

Provide:

- Move Up
- Move Down
- Remove
- Clear
- drag-to-reorder if practical

Do not automatically reorder screenshots by filename unless the user explicitly chooses that behavior.

# IMPORTANT: DO NOT FLATTEN THE SCREENSHOTS INTO ONE IMAGE

The purpose of this module is NOT to simply:

upload screenshot → place screenshot as one flat PSD layer

Instead, the system must analyze the screenshots and reconstruct their internal content as editable PSD elements wherever possible.

The system should detect:

- text areas
- headings
- body text
- captions
- labels
- product images
- lifestyle images
- banners
- icons
- tables
- charts
- backgrounds
- colored blocks
- section boundaries
- multi-column layouts

# TEXT EXTRACTION

Use OCR / text recognition to extract visible text from the screenshot.

Where reasonably possible, convert detected text into editable Photoshop text layers.

Examples:

TITLE
BODY_TEXT_01
BODY_TEXT_02
CAPTION_01

Preserve as much as possible:

- text position
- approximate font size
- approximate font weight
- alignment
- text box width
- line breaks
- text color

IMPORTANT:

Do not claim or assume the exact original font can always be recovered from a screenshot.

If the exact font cannot be identified:

- use the closest available font or a configurable fallback
- keep the text editable
- preserve approximate size and layout
- allow the designer to manually replace the font afterward

The priority is editability and correct structure, not perfect font identification.

# IMAGE EXTRACTION

Image-heavy areas should be separated from text wherever possible.

Examples:

product photos
lifestyle photos
detail photos
icons
feature illustrations
size diagrams
charts

These should become separate PSD layers instead of remaining embedded in one flat screenshot whenever feasible.

Suggested layer names:

IMG_01
IMG_02
PRODUCT_IMAGE
DETAIL_IMAGE
ICON_01
CHART_01

If an image cannot be reliably separated from surrounding design elements, keep that area as a cropped raster layer instead of generating a broken extraction.

Quality is more important than aggressive extraction.

# BACKGROUND / GRAPHIC AREAS

Detect simple backgrounds where possible:

- solid colors
- white backgrounds
- black backgrounds
- simple rectangular color blocks

Recreate them as separate fill/background layers when reliable.

If reconstruction is uncertain, preserve that section as a raster layer rather than damaging the visual result.

# SCREENSHOT ORDER AND SECTION STRUCTURE

Each uploaded screenshot should become its own logical PSD group.

Example:

LP_NAME.psd

03_LP_PART_02
04_LP_PART_03
05_LP_PART_04

Inside each LP group:

BACKGROUND
IMAGES

├─ BG
├─ IMG_01
├─ IMG_02
├─ TITLE
├─ BODY_01
└─ CAPTION_01

The exact hierarchy can be improved, but keep the PSD organized and easy for designers to edit.

# POSITIONING RULE

Every LP screenshot must be normalized proportionally to:

1000 px width

Do not stretch or distort the screenshot.

All reconstructed elements must use the normalized 1000 px coordinate system.

If an uploaded screenshot originally measures:

750 × 1200

it becomes proportionally:

1000 × 1600

All detected elements should be mapped into that normalized size.

Landing Page Part 1

then directly:

Landing Page Part 2

then:

Landing Page Part 3

etc.

There must be no automatically added blank space between LP parts.

# MULTIPLE SCREENSHOT COVERAGE

Every uploaded screenshot must be included.

No screenshot should:

- overlap another screenshot
- be reordered unexpectedly

The final height should equal:

normalized height of Screenshot 2

normalized height of Screenshot 3

If no Single is included but reserved Single space is enabled, still add the 1000 px top area.

# FALLBACK RULE

Do not force unreliable OCR or image extraction.

Use this priority:

1. Editable reconstruction if reliable
2. Partial editable reconstruction if partially reliable
3. Raster fallback for that specific section if reconstruction is unsafe

Do NOT let one difficult section destroy the entire LP.

The final PSD must always remain visually complete.
